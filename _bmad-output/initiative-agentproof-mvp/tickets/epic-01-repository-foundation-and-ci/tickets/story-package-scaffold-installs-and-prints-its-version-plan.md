## Intent

**Problem:** The repository holds planning documents and no code. Nothing can be built, installed, or checked until a package exists that installs from a wheel and answers `agentproof version` (story 1.1, epic 1 R1 and R2).

**Approach:** Create the `src` layout under `packages/python` exactly as the architecture spine's Structural Seed lists it, with `pyproject.toml` as the single version source, four runtime dependencies, a Typer app exposing only `version`, a uv lockfile, the OQ-1 decision stub, and two tests: a unit test that the version equals package metadata, and a smoke test that builds the wheel, installs it into a fresh venv, and runs `agentproof version`.

**Decisions delegated by the maintainer (2026-10-22, "approve all, you are the owner"):**
- The installed uv 0.2.37 lacks `uv build`; update uv to the current release (spine Stack pins 0.13.x) with `uv self update` before any package work, and record the resulting version in Implementation Notes.
- Use the uv-managed Python 3.13 already on this machine for local verification; install 3.12 through uv only if the download succeeds. The CI matrix (story 4) proves 3.12 to 3.15.
- Distribution name stays the provisional `agentproof` with the OQ-1 comment and stub; package version is `0.1.0.dev0`.

## Boundaries & Constraints

**Always:** Keep `pyproject.toml` the only place the version is written; expose `__version__` through `importlib.metadata`; keep `agentproof.__all__` to `["__version__"]`; keep every subpackage `__init__.py`, `errors.py`, and `constants.py` empty apart from a one-line docstring; runtime dependencies exactly `pydantic`, `typer`, `rich`, `pyyaml` with the spine's bounds; `requires-python = ">=3.12,<4"`; hatchling as the build backend; tests under `packages/python/tests/`.

**Never:** No command other than `version`; no error handler, exit-code module, or fault injection (story 3.1); no ruff, mypy, import-linter, or check entry point (stories 2 and 3); no CI (story 4); no hygiene files beyond the decision stub (story 5); no LICENSE; no edits to `AGENTS.md` or `PROJECT_SPEC.md`; no network access from the package itself; no `pip install` by name from PyPI anywhere in tests (the wheel path is used).

## I/O & Edge-Case Matrix

| Scenario | Input / State | Expected Output / Behavior | Error Handling |
|----------|--------------|---------------------------|----------------|
| Version from installed wheel | wheel from `uv build` installed into a fresh venv; `agentproof version` | prints the `pyproject.toml` version on one line, exit 0 | No error expected |
| Version from the dev environment | `uv run agentproof version` inside `packages/python` | same version string, exit 0 | No error expected |
| Public API surface | `import agentproof` | `agentproof.__all__ == ["__version__"]` and `agentproof.__version__` equals `importlib.metadata.version("agentproof")` | No error expected |
| Help lists only version | `agentproof --help` | the commands section lists `version` and nothing else | No error expected |
| Unknown command | `agentproof validate x.yaml` | Typer's usage error, non-zero exit; not asserted beyond non-zero, story 3.1 fixes the code | Typer default |

**2026-10-22 — implementation (Claude, delegated build)**

Tooling:
- `uv self update` on the PATH uv (0.2.37) failed with exit 2: that binary is a pip-installed copy inside `C:\Program Files\Autosphere\SDK\Scripts`, and self-update only works for standalone installs. A second copy at `%LOCALAPPDATA%\hermes\bin\uv.exe` is 0.12.5; neither was used.
- Resolution: ran the official standalone installer (`irm https://astral.sh/uv/install.ps1 | iex` with `UV_NO_MODIFY_PATH=1`), which put uv 0.13.5 into `C:\Users\M M\.local\bin`. That directory already precedes the Autosphere SDK on the user PATH, so a fresh shell resolves `uv` to the new binary without any PATH or SDK change. `uv self update` now reports "already on version v0.13.5 (the latest version)".
- **Resulting uv version: `uv 0.13.5 (46776a95d 2026-10-21 x86_64-pc-windows-msvc)`** (spine Stack pins 0.13.x).
- `uv python install 3.12` succeeded (CPython 3.12.15, 2m12s download), so per the delegated decision the environment was synced with `--python 3.12`. The new uv still sees the older managed 3.13.16 and 3.11.16. Side effect: uv 0.13 also dropped a `python3.12.exe` launcher into `~/.local/bin` (same pattern as the pre-existing `python3.11.exe`); it does not shadow `python`.

Decisions made while implementing:
- `cli/app.py` carries an empty `@app.callback()`. Typer collapses an app with exactly one `@app.command()` into a single-command app, in which case `agentproof version` fails with "unexpected extra argument"; the callback keeps `version` a subcommand and makes `--help` show a Commands section. The callback docstring is the app's one-line description.
- `__init__.py` imports `importlib.metadata.version` under a private alias so `__all__` and the module namespace expose only `__version__`. A docstring note records that the lookup key is the distribution name and must move with OQ-1.
- Subpackage `__init__.py` files hold one docstring each naming the owning AD from the spine; `errors.py` and `constants.py` likewise. No code.
- `[build-system] requires = ["hatchling>=1.27"]`; wheel built from `packages = ["src/agentproof"]`. No sdist configuration: hatchling found the repo-root `.gitignore` by walking up and excluded `.venv/` (verified by listing the sdist, 22 KB, which also copies that `.gitignore` in as its own, standard hatchling behaviour).
- Unit test adds a third assertion beyond the plan's two: `__version__` equals the `version` read from `pyproject.toml` with `tomllib`, which is the direct statement of the single-source rule (epic R2).
- Smoke test locates uv via the `UV` environment variable that `uv run` exports, falling back to `shutil.which`, and fails loudly if neither exists. It builds with `uv build --wheel --out-dir <tmp>` so no `dist/` lands in the tree, creates the venv with `uv venv --python sys.executable` (same interpreter as the test session), installs with `uv pip install --python <venv python> <wheel path>` (path, never a name), and runs the console script directly. It also asserts the wheel filename is `agentproof-<pyproject version>-py3-none-any.whl` and that `agentproof validate x.yaml` exits non-zero (matrix row 5; nothing beyond non-zero).
- First run of the smoke test failed on the `--help` parser: Rich chooses the panel border from the terminal, so under `TERM=dumb`/UTF-8 the installed CLI drew square corners (`┌ └`), the Git Bash console drew ASCII (`+-`), and the parser only knew rounded `╰`. Rewritten to end the Commands section at any line consisting solely of border characters (rounded, square, or ASCII) or, for click's plain layout, at the first blank line after an entry. Exercised against all four layouts plus a two-command case (returns `['run', 'version']`), then all tests passed.

Observed:
- `uv lock`: "Resolved 19 packages"; `uv sync --python 3.12`: venv created, 19 packages installed. Resolved runtime versions sit exactly on the spine lower bounds: pydantic 2.14.1, pydantic-core 2.50.1, typer 0.27.3, rich 15.0.0, pyyaml 6.0.3; pytest 9.1.1. uv warned that hardlinking from the cache fell back to copying (different filesystems); harmless.
- `uv run pytest -q`: `6 passed in 11.38s` (3 unit, 3 integration).
- `uv build`: built `dist/agentproof-0.1.0.dev0.tar.gz` and `dist/agentproof-0.1.0.dev0-py3-none-any.whl`. Wheel contents: the 16 source files plus `METADATA`, `WHEEL`, `entry_points.txt` (`agentproof = agentproof.cli.app:main`), `RECORD`. METADATA: `Requires-Python: <4,>=3.12`, `Requires-Dist` for exactly pydantic, pyyaml, rich, typer with the planned bounds. uv writes `dist/.gitignore` containing `*`, so build output is self-ignored; `dist/` was deleted after inspection anyway.
- `uv run agentproof version` -> `0.1.0.dev0`, exit 0. `uv run agentproof --help` -> exit 0, Commands panel lists `version` only. `uv run agentproof validate x.yaml` -> "No such command 'validate'", exit 2. `uv run agentproof` with no arguments prints help and exits 2 (click 8.2+ behaviour for `no_args_is_help`; not asserted, story 3.1 owns exit codes).

Risks and follow-ups:
- The `--help` smoke assertion depends on help-output layout. It survived four layouts here, but a future Typer/Rich change to panel drawing could break it; a `CliRunner`-based check would be more stable if that happens.
- The smoke test needs network (or a warm uv cache) the first time it resolves hatchling and the four runtime dependencies for the fresh venv; the package itself still makes no network calls.
- Story 5 must add `__pycache__/` and `dist/` to `.gitignore`; until then `git status` shows bytecode after any test run.
- The Autosphere SDK's stale uv 0.2.37 still exists and would be picked up by any shell whose PATH omits `~/.local/bin`.

**2026-10-22 — review fixes (Claude, delegated build)**
- `tests/unit/test_cli_version.py` (file added by the coordinator after the first hand-back): `test_help_lists_only_version_command` now keeps the `CliRunner` `--help` exit-code check and asserts the registered command set in-process. The prescribed `[c.name for c in app.registered_commands] == ["version"]` fails with `[None]`, because Typer's `CommandInfo.name` stays `None` until the Click group is built and the name is derived from the function; the assertion therefore uses Typer's own derivation: `list(get_command(app).commands) == ["version"]` (`from typer.main import get_command`). A separate-process mutation check confirmed it reports `['version', 'validate']` once a second command is registered. Result: `uv run pytest -q tests/unit/test_cli_version.py` -> 2 passed.
- `tests/integration/test_install_smoke.py`: `_run` sets `COLUMNS` to `"400"` with a comment explaining that a wrapped description continuation line would be read as a command by `_commands_listed_in_help`. Result: `uv run pytest -q tests/unit/test_cli_version.py tests/integration/test_install_smoke.py` -> smoke tests passed (the one failure in that run was the `[None]` case above, fixed afterwards). `uvx ruff check` and `ruff format --check` on both files: clean.
