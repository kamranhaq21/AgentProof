## Contradictions (PRD conflicts with spec)

- [spec §6.1] "`3`: execution/integration error" vs [PRD AC-21.3 + AC-27.2, addendum §C] — AC-21.3 converts an Adapter exception into a Scenario `error` and continues; AC-27.2 makes an error-only Suite exit 1; addendum §C says "3 is reserved for Adapter and I/O failures". Under the PRD text an Adapter crash therefore exits 1, under the addendum and the spec it exits 3, and no FR or AC in the PRD ever triggers 3 even though AC-27.1 requires an integration test for every code. Spec should win: an Adapter exception is an execution/integration error, distinct from "an assertion could not be evaluated on a valid Trace". Resolve OQ-3 by defining: Assertion `error` on a present Trace maps to 1; Adapter/I-O failure maps to 3; and the Suite-level precedence when both occur.
- [PRD §1] "answer three questions in one command" vs [spec §21] "answer three questions quickly" — the third question ("did the latest change make it worse") needs `run` then `compare` per FR-25/FR-26; the PRD's own CLI design contradicts its vision line. Spec should win; soften to "in one workflow" or make `run --baseline` an FR.
- [PRD FR-19, FR-30 "`trace replay`"] vs [addendum §C lean "rename to `trace evaluate`"] vs [spec §4 principle 11] "Replay means deterministic re-evaluation of recorded evidence unless a live re-run is explicitly requested" — the spec defines "replay" deliberately and uses it in §1.3, §2.2, §3.1, §6.5, §14.4; the addendum leans to abandoning the term while the PRD keeps it. Not a spec violation (spec §6.1 permits renaming), but the PRD and addendum disagree with each other and the spec's vocabulary. Decide OQ-4 one way and align Glossary, FR-19, FR-30, and README wording.
- [PRD UJ-1] "opens the uploaded HTML Report, sees Event 7 is the offending tool call with its arguments" vs [PRD FR-22, FR-23] — see Gaps; the journey claims a capability no FR requires. PRD-internal; fix the FRs, not the journey, because spec §2.1 Persona A requires trace-level debugging.
