Lenses: `structure`, `prose` (bmad-review). Reader type: humans. Style guide: Microsoft Writing Style Guide. Reviewed 2026-10-22. Nothing in the targets was edited.

**Read of purpose and audience:** the PRD exists to help the maintainer, the architecture spine, and the Product Owner turn `PROJECT_SPEC.md` into stably-identified, testable requirements they can slice and build from; the addendum exists to park the evidence and architecture inputs the PRD deliberately keeps out. **Structure model:** Strategic/Context (Pyramid) for the PRD; Reference/Database for the addendum.

**Word metrics** (`word_metrics.py`): PRD 9,373 words (§3 Glossary 757, §8 Hypotheses 689, §10 Open Questions 586, §11 Assumptions Index 401, §4.8 Description 67); addendum 1,292 words (§A 657).

**Constraints honored:** FR/AC/NFR/OQ/UJ/SM/H ids and numbering untouched; `[ASSUMPTION: ...]` and `[NOTE FOR PM: ...]` tags stay inline; Glossary terms used verbatim and capitalized; no fix below changes meaning, scope, or an acceptance criterion. Items that would are listed under "Out of scope for polish".

Severity: **high** = a reader of the document in its intended use (slicing, architecture, Ctrl-F navigation) is misled or blocked; **medium** = measurable friction; **low** = consistency.

## Structure findings

- **[high]** §10 Open Questions — MOVE/format. Every reference in the PRD is `OQ-n` (58 occurrences across ACs, tags, §8, and §11), but §10 renders the items as a bare Markdown ordered list (`1.`, `2.` ...), so Ctrl-F for `OQ-13` from AC-5.3 or NFR-6 never lands in §10, and an inserted line would silently renumber a frozen id. Word impact: +19. *Fix:* prefix each item with its explicit id, e.g. `1. **[B] Distribution and import name.**` → `1. **OQ-1 [B] Distribution and import name.**`; `2. **License.**` → `2. **OQ-2 License.**`; `3. **[B] Status precedence and Exit Codes.**` → `3. **OQ-3 [B] Status precedence and Exit Codes.**`; and so on through `19. **OQ-19 Positioning against EvalView, Promptfoo trajectory asserts, and agentevals**`. Also add, after the §10 intro line, a one-line index so the five blockers are findable without scanning: `Blockers: OQ-1, OQ-3, OQ-5, OQ-7, OQ-18.`

- **[high]** FR-2, lines for AC-2.5 and AC-2.4 — MOVE. AC-2.5 is listed before AC-2.4, which reads as a numbering error and makes the "all violations, not only the first" rule look like an afterthought. Ids stay as they are; only the line order changes. Word impact: 0. *Fix:* swap the two bullets so the FR-2 list reads AC-2.1, AC-2.2, AC-2.3, AC-2.4 (`agentproof validate SUITE_PATH` exits 0 ...), AC-2.5 (Scenario ids match ...).

- **[high]** addendum §A competitor table — MOVE. Eight columns with 40 to 80-word cells and a `Sources` column holding three URLs per row make the table unreadable at any normal width, and the (i) to (iv) legend forces the reader to look back for every column. Word impact: about −30 (legend absorbed into headers). *Fix:* (1) replace the header row `| Tool | License | Latest release seen | i | ii | iii | iv | Sources |` with `| Tool | License | Latest release seen | Tool-call assertions | Offline re-evaluation | CI gate | Local, no account | Sources |` and delete the `Legend: (i) ... (iv) ...` line; (2) move the URLs out of the cells into a numbered `Sources` list directly under the table, and replace each cell with bracketed numbers, e.g. the DeepEval row ends `| [1] [2] [3] |` and the list reads `1. pypi.org/project/deepeval` / `2. deepeval.com/docs/metrics-tool-correctness` / `3. deepeval.com/guides/guides-regression-testing-in-cicd`, continuing through the six tools.

- **[medium]** §8 Hypotheses and Evidence — MOVE (front-load). - **[medium]** §5 Non-Goals (Explicit) and §6.2 Out of Scope for MVP — QUESTION/scaffolding. ## Prose findings

Voice noted and preserved: terse, declarative requirement prose; capitalized Glossary terms; code spans for literals; one-sentence FR leads followed by testable ACs; inline bracketed tags. Fixes are the smallest change that removes the obstacle. Passages the structure pass moved keep their fixes attached to the surviving location.

- **[high]** FR-27 lead sentence — the exit-code map reads `0 all required checks passed; 1 one or more Assertions failed or errored; 2 invalid ...`, where "1 one" and the unseparated code/meaning pairs make the single most-referenced mapping in the document hard to parse. *Fix:* `Every command exits with a documented code: 0, all required checks passed; 1, one or more Assertions failed or errored; 2, invalid configuration or input; 3, execution or integration error; 4, internal unexpected error.`

- **[high]** §11 Assumptions Index, entry `§3 Suite defaults` — the index says the v0.1 defaults set is `adapter`, `fail_on_missing_trace`, `compare.include_arguments`, but the Glossary entry it indexes lists four keys including `redact`. The index is the derived text; align it with the Glossary (the source). *Fix:* replace `- §3 Suite defaults — The v0.1 defaults set is `adapter`, `fail_on_missing_trace`, `compare.include_arguments`.` with `- §3 Suite defaults — The v0.1 defaults set is `adapter`, `fail_on_missing_trace`, `compare.include_arguments`, and `redact`.`

- **[medium]** NFR-8, inside the `[ASSUMPTION: ...]` tag — `the addendum's `major.minor` lean is withdrawn` points at a lean the addendum no longer holds (addendum §C now leans `integer, per PRD NFR-8` and records `major.minor` as withdrawn). Stale cross-reference; tag stays inline. *Fix:* `[ASSUMPTION: integer versions with forbid-unknown; the `major.minor` alternative was considered and withdrawn (addendum §C); OQ-5]`

- **[medium]** §10, OQ-5, OQ-7, OQ-8, OQ-9, OQ-16 — the pattern "<long noun phrase> assumed (AC-n)" puts the verb last and makes the current assumption hard to spot, e.g. `Integer Schema Versions with unknown fields rejected assumed (NFR-8), which makes every additive field a new version; the alternative is ...`. Lead with the label. *Fix:* OQ-5: `Assumed: RFC 3339 with offset (AC-5.3); integer Schema Versions with unknown fields rejected (NFR-8), which makes every additive field a new version. Alternative: `major.minor` with additive tolerance, which conflicts with AC-2.2. Does Final Output live on `agent_finished` or at run level?`; OQ-7: `Assumed: dotted keys with list indexes (AC-14.1). Alternatives: JSONPath or JMESPath, each adding a dependency.`; OQ-8: `Assumed: intervening Events allowed and first-occurrence ordering (AC-15.1, AC-15.4). Alternatives: every occurrence must respect the order; a `strict` adjacency option.`; OQ-9: `Assumed: case-sensitive, no Unicode normalization, canonical JSON for structured output (AC-16.1, AC-16.2).`; OQ-16: `Assumed: default `./agentproof-output/` (AC-30.1). Open: which directories hold committed example Traces versus local Traces that must be gitignored.`

- **[medium]** §1 Vision, first paragraph — two sentences carry the whole problem statement, and both are overloaded: the first chains three "and"s where the last is a contrast, and the second runs 60 words to a trailing clause about competitors. *Fix:* `AI agents call tools, change state, and make multi-step decisions; a fluent final answer proves none of that happened correctly. Few teams have a repeatable, repository-local way to check that the agent still calls the right tools, with the right arguments, in the right order, and never calls the forbidden ones. The tools that offer such checks (§8 H6) tie them to a test framework, a server, or a hosted account.`

- **[medium]** AC-14.2 — a precise matching rule written as one comma series with internal commas: `numbers compare numerically (`1` equals `1.0`), strings, booleans, and null compare exactly, and a number never matches a string`. The reader cannot tell where one rule ends. *Fix:* `Matching compares JSON values by value: numbers compare numerically (`1` equals `1.0`); strings, booleans, and null compare exactly; a number never matches a string (`5` and `"5"` do not match). Objects and arrays match by deep equality.`

- **[medium]** AC-5.4 — `the rule that `llm_request` carries metadata only while `llm_response` content is redaction-sensitive` reads "while" as temporal ("only while ... is sensitive") when it is a contrast. *Fix:* `The Event metadata schema, and the rule that `llm_request` carries metadata only whereas `llm_response` content is redaction-sensitive, are documented in the Trace reference.`

- **[medium]** §8 intro and H6 evidence cell — two unclear constructions in the section a PM must act on. (1) `This table states only what it changes.` has no clear antecedent for "it". (2) `What no single tool found in the pass combines: YAML Scenarios, ...` is a fronted clause that most readers parse twice. *Fix:* (1) `The table below states only what that evidence changes.`; (2) `No single tool found in the pass combines all of: YAML Scenarios, a versioned framework-neutral Trace file format, Replay from a file with no server, and a self-contained HTML Report.` (apply in the H6 detail paragraph if the structure move is accepted).

- **[low]** §3 Glossary `Redaction` and FR-31 lead sentence — each is a single 60 to 70-word sentence stacking four qualifiers; split once, no content change. *Fix:* Glossary: `Replacing configured secret-like values in a Trace with a fixed marker as soon as the Trace enters the runner, before Evaluation and before any write or terminal output. The replacement is recorded as redaction state on the artifact and as a redaction marker on each affected Event. A live Run and a Replay of its exported Trace therefore evaluate identical data.`; FR-31: `The system replaces, in Trace Events and Final Output, the values of configured keys (default set: `api_key`, `token`, `password`, `authorization`, plus user-specified paths) and every occurrence of the current value of each environment variable named under `redact.env` (for example `OPENAI_API_KEY`) with a fixed marker. Replacement happens before Evaluation and before any output.`

- **[low]** AC-1.4, AC-2.5, AC-5.2, AC-7.1, AC-7.2, AC-15.2 — the "rejected naming X" / "Fails naming X" construction appears both with and without a comma (AC-2.2, AC-2.3, AC-3.1, AC-3.2 use `rejected, naming`); without the comma it momentarily reads as "rejected-naming". One consistent form. *Fix:* insert the comma in the six listed ACs: `rejected, naming the key and line` (AC-1.4); `rejected, naming the id` (AC-2.5); `rejected, naming the type and sequence index` (AC-5.2); `rejected, naming both versions` (AC-7.1); `rejected, naming the first offending index` (AC-7.2); `Fails, naming the first tool found out of order` (AC-15.2).

- **[low]** AC-27.1, AC-29.3, AC-31.1 — bare `[ASSUMPTION]` tags with no statement, while every other tag states what is assumed; the reader must jump to §11 to learn what is provisional. Tags stay inline; copy the §11 statement into the tag. *Fix:* AC-27.1: `[ASSUMPTION: exit code 4 is reached through a test-only fault-injection variable]`; AC-29.3: `[ASSUMPTION: Reports and Traces are written atomically via temp-file-and-rename]`; AC-31.1: `[ASSUMPTION: default Redaction keys match case-insensitively at any depth]`.

- **[low]** addendum §B and §D — three small ambiguities for a reader who arrives from the PRD. (1) `rich terminal output`: `rich` is the library, but reads as an adjective. (2) `(spec §9 overrides the §8 tree)`: `§8` in a PRD-adjacent document reads as PRD §8 Hypotheses. (3) `FR ids in this PRD map onto them` in §D: the addendum is not the PRD. *Fix:* (1) `Typer CLI, `rich` for terminal output,`; (2) `(spec §9 overrides the spec §8 tree)`; (3) `FR ids in the PRD map onto them`.

**Prose summary:** 12 recommendations (2 high, 6 medium, 4 low). 9 further minor fixes (comma and series punctuation in §2.1 annotations, SM-C1 subject agreement, §4.6 "Comparison is ... comparison", OQ-1 "Blocks" ordering, §6.2 wording parity with the FR-24 heading, and similar) were left out as below the usability bar; ask to expand.

## Out of scope for polish (would change meaning, scope, or an AC)

- **AC-18.1** — `passed` if all passed or skipped` and `skipped` if all skipped` overlap: an all-skipped Scenario satisfies both clauses, and precedence is only implied by order. A disambiguation (`passed` if every Assertion passed or skipped and at least one passed`) would change the AC text.
- **NFR-4** — `Redaction is applied before any write when configured` can be read as "off unless configured", which conflicts with FR-31's default key set that applies without configuration. Clarifying which reading holds is a requirement decision.
- **§5 Non-Goals** — the `in v0.1` qualifiers on "Not a hosted service" and "Not a general LLM evaluation platform" make those boundaries time-boxed while the rest of §5 is permanent; removing or keeping the qualifier is a scope decision (the structure pass adds a lead-in sentence instead).
- **AC-27.1** — `test-only fault-injection environment variable that is ignored in release builds unless explicitly enabled` leaves open whether release builds can enable it at all; resolving that changes the AC.
- **AC-12.4 / FR-13** — the `tool_call_count` with `less_than` rule arguably belongs to FR-13 as its own AC; that would mint a new AC id, so the structure pass adds a pointer only.
- **addendum §B, first bullet** — lists pytest, ruff, and mypy/pyright alongside runtime libraries and then says `Keep the runtime dependency list to this set`; separating runtime from development dependencies is an architecture statement, not a wording fix.
