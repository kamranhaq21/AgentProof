# Spine Review — AgentProof v0.1

Reviewed: `architecture-agentproof.md` (AD-1..AD-18) and `adr-log.md` (ADR-001..018) against `prd-agentproof.md` (FR-1..FR-35, NFR-1..NFR-10, OQ-1..OQ-19) with `addendum.md` as context. Date: 2026-10-22.

## Verdict

The spine is a usable build substrate: terse, invariants first, and it fixes most of the places where independently built epics would otherwise drift (status fold, exit codes, error taxonomy, canonical form, redaction point, artifact names, public API). It is not yet safe to hand to parallel agents because the dependency graph is specified three different ways that disagree (AD-2 diagram, ADR-002 layer contract, AD-8 registry-union), the status fold in AD-6 contradicts AC-18.1, and the core/shell boundary for file reads is undefined while `load_suite`/`load_trace` sit in the public API. Fix the one critical and three high findings and the rest can be absorbed as story-level corrections.

## Checklist

- **1. Divergence coverage — adequate.** The high-traffic divergence points are pinned: one status fold and one exit-code function (AD-6), one error taxonomy (AD-7), one serializer and one volatile-field list (AD-11), one redaction point (AD-10), fixed artifact names (AD-13), one public `__all__` (AD-14), a frozen Pydantic contract with integer versions (AD-3/AD-4). Missed: where a file is read and size-checked versus where it is parsed (the `loading` package is "core" but `load_suite(path)` is public API); the shape of the suite-level run result that AD-6 depends on (`run.execution_failed`, `run.evaluated_assertions` belong to a type named nowhere); how a Report is loaded for `compare` and `report` (no `loading/report.py`); how the Fixture Agent finds its trace files and is made deterministic (AC-20.2); whether the runner catches arbitrary exceptions from `Adapter.run` (AC-21.3). Each of these is a seam between two epics, and each would be resolved differently by two agents.

- **2. Enforceable rules — adequate.** Most rules name a checker: import-linter (AD-2, AD-14), ruff banned-api (AD-1), schema-drift test (AD-4), conftest socket/subprocess guard and secret-leak grep (AD-16), test vectors (AD-12), pyproject inspection (AD-15). Weak spots: AD-1 bans "`pathlib` write methods" and `datetime.now`, which ruff TID251 cannot see on an instance receiver (`path.write_text(...)`); banning `open` and `pathlib` outright in the core would be checkable. AD-8's rule ("the Suite model's `assertions` field is a discriminated union built from the registry") is enforceable but, as written, requires `models` to import `assertions`, which AD-2 forbids, so the enforcement tool (import-linter) would reject the only compliant implementation. AD-6 is enforceable but encodes the wrong precedence for `skipped` (see Findings), so it prevents divergence by making everyone agree on a value that contradicts the PRD.

- **3. Deferred — strong.** Nothing under Deferred lets two v0.1 units diverge: the viewer, extra assertions, JUnit, OTel import, and storage are all behind a fixed seam (AD-3/AD-4 schema, AD-8 protocol, AD-9 protocol, AD-11 renderer rule). The only soft spot is the check task runner (ARCH-4): if two EPIC A stories run in parallel, one may add `poe` and the other `nox`; the Open Decisions table says "settle before coding", which is sufficient if EPIC A's first story is sequential. OQ-12 (size limit) is absent from both Deferred and Open Decisions, so it is neither deferred nor decided (Finding 4).

- **4. Verified-current tech — thin.** Python 3.12/3.13/3.14, PyYAML >=6.0.3, pytest >=9.1, pytest-cov >=7.1, jsonschema >=4.26, pip-audit >=2.10, ruff >=0.17 and hypothesis >=6.170 are consistent with release cadence as of 2026-10-22. `mypy >=2.4` looks invented: mypy has been on a 1.x line with roughly monthly minors since 2023 and no 2.0 is known to this reviewer; a floor of 2.4 would require a major bump plus four minors. `import-linter >=2.15` is suspicious for the same reason (cadence of three to four minors a year from 2.0 in mid-2024 lands near 2.8-2.9). `uv 0.13.x`, `typer >=0.27`, `rich >=15`, `pydantic >=2.14` are plausible extrapolations but unverified. The Stack table also omits the task runner that AD-17 names (`poe`). Nothing here is architectural; it needs one EPIC A story that runs `uv lock` and rewrites the table from the lockfile.

- **5. PRD drove it — adequate.** Every FR-1..FR-35 and NFR-1..NFR-10 appears in the Capability map, and the Deferred list names the PRD open questions it waits on (OQ-11, OQ-15, OQ-18). The quiet requirements fared worse. Honesty-of-claims ACs have no home: AC-26.6 (compare output states it is an exact comparison of saved data, not a reproducibility claim), AC-31.4 and AC-33.3 (docs state redaction limits and the §5 limits), AC-32.3 (artifact visibility warning), AC-12.4 (negative assertions and `less_than` state the Capture declaration in their message and the Report shows it). AC-5.5 (environment metadata allowlist; never hostnames, user names, or env vars) is a privacy claim with no AD and no test in AD-16. AC-21.5 (adapter conformance suite) is not placed. NFR-10's "Events referenced by Evidence render expanded even beyond 500" was dropped from AD-12. NFR-2 and NFR-5 are mapped to AD-10/AD-12/AD-16/AD-18 and AD-7/AD-16, none of which says anything about YAML or JSON parsing.

- **6. Dimensions owned at this altitude — adequate.** Decided: module boundaries (AD-1, AD-2, seed), data model (AD-3, AD-5), public API (AD-14), schema versioning (AD-3), adapter port (AD-9), error semantics (AD-7), rendering security (AD-12), redaction (AD-10), testing (AD-16), CI (AD-17), repository layout (seed), dependency policy (AD-15), deployment and environments (operational envelope), operations (none by AD-18). Silent or thin: **parsing security** has no AD (safe loader, alias and duplicate-key rejection, multi-document rejection, size check before parse, JSON size and nesting) despite being named in the dimension list and carrying four PRD ACs; **CLI contract** is decided only by seed file names, AD-6 and the PRD (acceptable, but `--output` means a directory for `run` and a file for `report` per AC-23.6, and the spine fixes only the directory reading); **release** names trusted publishing but not the package-version source of truth (tag versus `pyproject.toml`) or the pre-1.0 semver policy that AD-14 refers to as "semver policy".

- **7. Build substrate — adequate.** The document is terse, leads with invariants, keeps the seed minimal, and pushes rationale to `adr-log.md` (ADRs carry Context/Alternatives; the spine does not). It contradicts itself and the ADR log in four places: (a) AD-2's diagram has `runner` importing `engine, redaction, adapters, io, loading` only, while ADR-002's layer contract puts `runner` above `{reports, compare}`; the spine's own AD-13 binds `runner` to artifact writing, which needs `reports.canonical.dumps`; (b) AD-8 needs `models.suite` to import `assertions.registry` while AD-2 has `models` below `assertions`; (c) the Design Paradigm says the core has "no filesystem" while AD-1's rule bans only `pathlib` write methods and AD-14 exports `load_suite`/`load_trace`; (d) the Conventions "Error shape: one line" contradicts AC-2.4 "printing all violations, not only the first". ADR-006 is marked Accepted while the spine lists OQ-3 as open; ADR-005 cites "PRD OQ-2 of the first review", which in the current PRD is the License question.

- **8. Assumptions and Open Decisions — adequate.** Tagged assumptions are tracked for AD-3 (OQ-5), AD-5 (ARCH-3), AD-9 (ARCH-2), AD-17 (ARCH-4), conventions (OQ-7, ARCH-1). Untracked: the AD-10 "values shorter than 8 characters are not scrubbed" assumption is not in the table and weakens FR-31 (a security property). Settled without a tag: OQ-4 (`trace replay` and `replay-<id>.report.json` are baked into AD-13 and the seed); OQ-16's default directory (`./agentproof-output/`, stated flat in AD-13); OQ-12 is dropped entirely. OQ-6, OQ-8, OQ-9, OQ-10 and OQ-17 are left with the PRD, which is correct for story-level semantics, but the table should say so, or a story agent will read their absence as closure.

## Findings

- **[critical]** Dependency graph specified three ways, and they disagree (AD-2, ADR-002, AD-8) — EPIC A writes `.importlinter` from one of these and every later epic builds against it. AD-2's mermaid has no `reports --> runner` or `compare --> runner` edge; ADR-002's contract is `... < engine < {reports, compare} < runner < cli`, which allows it. AD-8 makes `models.suite.Scenario.assertions` a discriminated union over `assertions.registry.REGISTRY`, so `models` imports `assertions`, but AD-2 has `models --> assertions` (assertions depends on models), a cycle. Concrete failure: the runner story cannot write `report.json` (AD-13 binds `runner`) without `reports.canonical.dumps`, and the models story cannot define `Scenario` without the registry. *Fix:* pick one graph and state it once. Suggested: move `assertions/base.py` (the `AssertionConfig` base and `AssertionResult`) into `models`; have `models.suite.Scenario.assertions: list[AssertionConfig]` typed against the base; build the concrete discriminated union in `loading.suite` with a `TypeAdapter` over `REGISTRY`; add edges `assertions --> loading`, `reports --> runner`, `compare --> runner` to the AD-2 diagram; rewrite ADR-002's contract to `errors < models < assertions < {loading, redaction, adapters} < engine < {reports, compare} < runner < cli`, `io` independent on `errors` only; state that `io.artifacts.write(path, text)` takes already-serialized text.

- **[high]** Status precedence contradicts AC-18.1 for `skipped` (AD-6) — AD-6 folds with `failed > error > skipped > passed`, so a Suite with one skipped and one passed Scenario has Suite Status `skipped`. AC-18.1 says `skipped` only "if every Assertion skipped, otherwise `passed`", and the same precedence applies over Scenario Statuses, so the PRD answer is `passed`. The Report's `suite_status` and every golden file would differ between an engine built from AD-6 and tests built from the PRD. *Fix:* "`combine` returns `failed` if any failed, else `error` if any errored, else `skipped` only if all inputs are skipped (or the input is empty), else `passed`." Keep the exit-code rule as is (`evaluated_assertions == 0` already covers the all-skipped run).

- **[high]** Core/shell boundary on file reads is undefined; `load_suite` and `load_trace` cannot be both pure and path-taking (Paradigm, AD-1, AD-14, AD-13) — the Paradigm says core has "no filesystem"; AD-1's rule bans only `pathlib` write methods; AD-14 exports `load_suite`, `load_trace`; AD-13's symlink refusal and AC-1.2's size check need the file handle. Two agents will resolve this as `load_suite(path: Path)` in core (reads a file, breaks AD-1) and `load_suite(text: str)` in core with a shell wrapper (different public signature). *Fix:* "`loading.*` functions take `data: str | bytes` and `source: str` (used only in error messages). `io.read_text(path, limit_bytes)` is the only file reader: it checks size before reading (AC-1.2), refuses symlinks resolving outside the given root when a root is supplied, and raises `PathError`. Public `load_suite(path_or_text)` and `load_trace(path_or_text)` live in `agentproof/__init__.py` as thin shell wrappers; `Path` input goes through `io.read_text`, `str` input is parsed directly. AD-1 bans `builtins.open` and the `pathlib` module in the core."

- **[high]** No AD for parsing security; OQ-12 (size limit) dropped (NFR-2, NFR-5, AC-1.1, AC-1.2, AC-1.4, AC-1.5, AC-1.6, AC-7.3) — the only trace is the seed comment "`yaml_safe.py (dup keys, no aliases, size)`" and `limits.py` with no number. NFR-2 is mapped to AD-10/12/16/18 and NFR-5 to AD-7/16, none of which mention YAML or JSON. A story agent could use `yaml.safe_load` (silent duplicate-key merge, aliases allowed) and satisfy every AD. *Fix:* add AD-19 "Parsing": `loading.yaml_safe.load(data, source)` uses a `SafeLoader` subclass that raises `SuiteError` on duplicate keys (naming key and line), on any alias or anchor, on any custom tag, and on a second document; `yaml.load`, `yaml.full_load`, `yaml.unsafe_load`, `pickle`, `eval`, `exec`, `marshal` are banned-api in the whole package; JSON is parsed with `json.loads` after the size check; `loading.limits.DEFAULT_MAX_BYTES = 5 * 1024 * 1024` `[ASSUMPTION: OQ-12]`, applied to Suite, Trace and Report files by `io.read_text`. Add OQ-12 to the Open Decisions table and map NFR-2/NFR-5 to the new AD.

- **[medium]** Suite-level run result and Report model shape are not fixed; no Report loader (AD-6, AD-3, seed) — AD-6 reads `run.execution_failed` and `run.evaluated_assertions` from a type that is not in `models/` (common, suite, trace, result, report) nor in `__all__`. `compare` and `report` both read a Report from disk, but `loading/` has no `report.py`, so each command would validate Reports differently (AC-25.1 needs exit 2 with a reason). Whether the Report embeds whole `Trace` objects (with `capture`, `redaction`) or only `events` is unstated; the HTML renderer needs `redacted: true` per event (AC-23.5) and AC-12.4 needs the capture declaration label. *Fix:* name `models.result.RunResult` (fields: `scenarios: list[ScenarioResult]`, `execution_failed: bool`, `evaluated_assertions: int`, `suite_status`) and `models.report.Report` (per-scenario `trace: Trace` embedded whole, redacted); add `loading/report.py` and `load_report` to `__all__`; state that `from_run(run: RunResult)`.

- **[medium]** Adapter exception handling unspecified (AD-9, AD-7, AC-21.3) — AD-7 maps `AdapterRunError` to exit 3, but nothing says the runner catches an arbitrary `Exception` from `Adapter.run` and continues to the next Scenario. A runner built from AD-7 alone lets a `ValueError` from an adapter reach the last-resort handler (exit 4) and abort the Suite; AC-21.3 requires Scenario `error`, continue, and `execution_failed=True`. *Fix:* in AD-9: "The runner wraps `Adapter.run` in `except Exception as e: raise AdapterRunError(f'{type(e).__name__}: {e}') from e`, records the Scenario as `error` with that message, sets `run.execution_failed`, and continues with the next Scenario. The message passes through the console scrub (AD-10)."

- **[medium]** Fixture Agent configuration and determinism unspecified (AD-9, FR-20, AC-20.2, conventions "Ids") — FR-20 says the Fixture Agent returns "scripted Traces read from referenced Trace JSON files"; the spine never says where the reference lives (Scenario field? Suite defaults?), what the path is relative to (Suite file directory versus CWD), or how "configured deterministic" (fixed timestamps, run id from scenario id) is declared. AD-2 lets `adapters` import only `models` and `errors`, so `fixture.py` cannot use `io.read_text` and bypasses the size limit. The `init` story, the fixture story and the docs story will each invent a different field. *Fix:* "Suite defaults `adapter: fixture` plus per-Scenario `fixture: { trace: <path relative to the Suite file>, deterministic: true }`; the runner resolves the path and passes the already-read text in `RunContext.extra['fixture_trace']`"; or permit `adapters` to import `io`. Either way, add `fixture` to the Suite model and to the Conventions table.

- **[medium]** 8-character redaction floor weakens FR-31 and is untracked (AD-10, ADR-010, AC-31.3, AC-31.4) — FR-31 requires "every occurrence of the current value" of each named env var; AD-10 adds `[ASSUMPTION: values shorter than 8 characters are not scrubbed]`, which is a security exception not in the PRD and not in the Open Decisions table. A `redact.env: [PIN]` with a six-digit value would leak and AC-31.3's test would pass if the planted value happens to be long. *Fix:* add ARCH-5 to the table with the rationale (short values over-match), require the docs to state it (AC-31.4), and make the runner log a warning naming the variable when a declared value is skipped. Alternatively drop the floor and scrub every declared value regardless of length.

- **[medium]** Honesty-of-claims and privacy quiet requirements have no home (Capability map; AC-26.6, AC-31.4, AC-33.3, AC-32.3, AC-12.4, AC-5.5) — `compare` output must say it is an exact comparison of saved data; negative assertions and `less_than` must state the Capture declaration; docs must state redaction limits, §5 limits and artifact visibility; environment metadata must come from an allowlist. None is bound by an AD or convention; AD-16 does not test AC-5.5. A compare story could ship without the sentence and pass every AD. *Fix:* add a Conventions row "Claims": "`compare` prints the AC-26.6 sentence verbatim; `tool_not_called` and `tool_call_count(less_than)` messages end with `capture: <complete|partial|unknown>`; `docs/security.md` carries the AC-31.4, AC-33.3 and AC-32.3 statements and README links it." Add to AD-9: "`RunContext.environment` is built by the runner from `{package_version, python_version, os, source_revision?}` only" and to AD-16: "a test asserts no Trace field contains `os.environ` values, hostname, or user name."

- **[medium]** AD-12 drops "Evidence-referenced events always expanded" (NFR-10, AC-8.1, AC-23.4) — AD-12 says "beyond 500 events per scenario the rest collapse to a count and the JSON path as text." NFR-10 says the Report "renders Events referenced by Evidence expanded, and collapses the rest beyond the first 500". A failing assertion whose evidence is seq 1203 would render as a count, and the reader cannot "find the Event an Evidence index points at". *Fix:* "Events with `seq` in any Assertion Result's evidence are always rendered in full; of the remaining events the first 500 are rendered and the rest collapse to a count and a pointer to `report.json`."

- **[medium]** Error-shape convention contradicts AC-2.4 (Conventions "Error shape", AD-7) — "User-facing: one line `<kind>: <message> (<file>:<field>)`" versus AC-2.4 "`validate` ... printing all violations, not only the first". Pydantic `ValidationError` carries many errors; a CLI built from the convention prints the first. *Fix:* "One line per violation, same shape; `InputError` carries `violations: list[Violation(file, field_path, message)]` and the CLI prints each."

- **[medium]** Adapter conformance suite has no location (AC-21.5, AD-9, AD-14, seed) — "A generic conformance test suite checks what it can observe" is a v0.1 deliverable. If it is for third-party adapter authors it must ship in the wheel and is public API; AD-14's `__all__` does not include it and the seed has no `agentproof/testing/`. *Fix:* add `src/agentproof/testing/adapter_conformance.py` to the seed with `check_adapter(adapter, scenario, context)` and add `testing` to `__all__`, or state that conformance is a `tests/integration/` fixture run only against built-in adapters in v0.1.

- **[medium]** Stack versions partly unverifiable or invented (Stack table, ADR-002) — `mypy >=2.4` (mypy is a 1.x line; no 2.x known), `import-linter >=2.15` (cadence puts it near 2.8-2.9; ADR-002 also cites "import-linter 2.15" as the version), plus unverified `uv 0.13.x`, `typer >=0.27`, `rich >=15`, `pydantic >=2.14`. A pyproject written from this table will fail to resolve. *Fix:* EPIC A story "Pin stack": run `uv lock`, rewrite the Stack table from the lockfile with the actual lower bounds, and change the table header to "Version (from uv.lock YYYY-MM-DD)". Add the chosen task runner (`poethepoet` or none) to the table.

- **[low]** `--output` means a directory for `run` and a file for `report`; replay HTML name missing (AD-13, AC-23.6, AC-19.4) — AD-13 fixes `report.html` only; a replay Report's HTML would be `replay-<id>.report.html` by AC-23.6's "`<report name>.html`", but AD-13's fixed-name list does not include it, and `report --output PATH` is a file. *Fix:* in AD-13: "`report` writes `<json stem>.html` beside its input by default; its `--output` names a file; `run`'s `--output` names a directory. Fixed names: `report.json`, `report.html`, `scenario-<id>.trace.json`, `replay-<id>.report.json`, `replay-<id>.report.html`."

- **[low]** OQ-4 and OQ-16 settled implicitly; OQ-6/8/9/10/17 absent from the table (AD-13, seed, Open Decisions) — `trace replay` and `replay-<id>` bake in the command name the PRD left open (OQ-4); `./agentproof-output/` is stated flat (OQ-16), and whether example Traces are committed or gitignored is not addressed. *Fix:* add rows: "OQ-4 | replay name | AD-13 file name, `cli/commands/trace.py` | `replay`"; "OQ-16 | output dir and gitignore | AD-13, seed | `./agentproof-output/` gitignored; `examples/**/*.trace.json` committed"; and one row "OQ-6, OQ-8, OQ-9, OQ-10, OQ-17 | assertion and compare semantics | stories | PRD defaults as written; not re-decided here."

- **[low]** Scenario ordering in run and Report unspecified (AD-11, AD-6) — canonical form sorts keys, not lists; the order of `scenarios` in the Report, the order the runner executes them, and the order `compare` lists differences are each a choice. *Fix:* Conventions row "Order": "Scenarios execute and serialize in declared order; Assertion Results in declared order; `compare` lists Scenarios in Baseline order then added ones in current order."

- **[low]** `allow_nan` not pinned (AD-11, ADR-011) — ADR-011 says NaN and infinity are rejected by the models, but AD-11's `json.dumps(obj, sort_keys=True, indent=2, ensure_ascii=False)` keeps the default `allow_nan=True`, which would emit non-JSON `NaN` if a float slipped through. *Fix:* add `allow_nan=False` to the one serializer and a `JsonValue` validator `[finite floats only]`.

- **[low]** Example GitHub Actions workflow absent from seed; AC-32.1 job unnamed (FR-32, AD-17, seed) — the seed lists `.github/workflows/ci.yml release.yml`; FR-32's copy-paste workflow for users is a separate file, and AC-32.1 requires the project's CI to run it against the example Suite and upload the HTML Report. *Fix:* add `examples/expense-agent/.github-workflow.yml` (or `docs/ci/github-actions.yml`) to the seed and a line in AD-17: "CI job `example-workflow` runs that file's steps verbatim and asserts the uploaded artifact contains `report.html`."

- **[low]** Loose ends (Stack, AD-17, AD-18, Capability map, frontmatter) — `hypothesis` in Stack but no rule uses it; `poe` in AD-17 but not in Stack; `[ADOPTED]` tag on AD-18 is undefined (preface defines only `[ASSUMPTION]`); Capability map lists FR-24 as living in `reports` while Deferred moves it to v0.2; frontmatter `binds` includes FR-35 which is deferred. *Fix:* delete `hypothesis` or add a property-test line to AD-16; define `[ADOPTED]` or drop it; mark FR-24 and FR-35 "deferred" in the map; set `binds: ['FR-1..FR-23', 'FR-25..FR-34', 'NFR-1..NFR-10']`.

- **[low]** Package version source and pre-1.0 policy not stated (AD-14, operational envelope, NFR-8, AC-30.2) — AD-14 says "semver policy" and the envelope says "tag-driven"; whether the version lives in `pyproject.toml` or is derived from the tag, and what `agentproof version` reads, is open. *Fix:* "Version is static in `pyproject.toml`; `release.yml` refuses a tag that does not equal it; `agentproof version` reads `importlib.metadata.version`; before 1.0 a minor bump may break the public API with a CHANGELOG note."

## Mechanical

- **AD id continuity:** AD-1..AD-18 contiguous; ADR-001..ADR-018 one-to-one; no gaps or duplicates. Open Decisions use PRD ids (OQ-1, 2, 3, 5, 7, 13, 18) plus ARCH-1..4; PRD OQ gaps are intentional but unexplained (see Findings).
- **Binds/Prevents/Rule:** present on all 18 ADs. AD-9's Rule is a code block plus prose; fine. AD-18 carries an undefined `[ADOPTED]` tag.
- **Mermaid:** three diagrams parse as flowcharts. Labels containing colons and commas inside `[...]` and `[(...)]` are accepted by current mermaid; node ids `io`, `cli`, `errors`, `compare` are not reserved. Cross-subgraph edges in the first diagram are valid. One semantic concern: the first diagram shows `RUN --> LOAD` and `RUN --> ENG` but no `RUN --> REP`, matching the AD-2 diagram and contradicting ADR-002 (Finding 1).
- **Cross-references to PRD ids:** all FR/NFR/AC ids cited in the spine exist (AC-7.2, AC-28.2, AC-31.3, AC-27.3, AC-27.4, OQ-1/2/3/5/7/11/13/15/18). ADR-005 cites "PRD OQ-2 of the first review and OQ-5"; in the current PRD OQ-2 is the License question, so the first reference is dangling. ADR-010 cites AC-19.2 as the rule write-time redaction contradicts; the closer citation is AC-6.3 and the Glossary "Redaction" entry. "spec §12.4", "spec §7.2", "spec §6.9", "spec §10.3", "spec §9" refer to `PROJECT_SPEC.md`, not the PRD; acceptable but should say "spec" consistently (AD-16 does).
- **Spine versus adr-log contradictions:** (1) AD-2 diagram omits `reports --> runner`, `compare --> runner`; ADR-002 layer contract includes them. (2) AD-8 registry-union versus AD-2 `models` below `assertions`. (3) ADR-006 status "Accepted" while spine lists OQ-3 as open with the PRD default; harmless but should read "Accepted by default; OQ-3 open". - **Spine versus PRD contradictions:** AD-6 `skipped > passed` versus AC-18.1; Conventions "one line" versus AC-2.4; AD-10 8-character floor versus FR-31 "every occurrence"; AD-12 collapse rule versus NFR-10 evidence-expanded rule.
