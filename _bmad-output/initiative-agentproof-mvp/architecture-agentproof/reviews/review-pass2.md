# Second-pass Review — AgentProof v0.1 spine

Reviewed 2026-10-22: `architecture-agentproof.md` (AD-1..AD-20, revised) and `adr-log.md` (ADR-001..020) against the four first-draft reviews and `prd-agentproof.md`. Method for section "New findings": the adversarial technique re-run only on material that changed, building pairs of independently written units that each obey every AD as written and still fail to compose.

## Verdict

The revision closes every critical and all but one high finding from the first pass: the dependency graph is now written once and the diagram mirrors it, the fold matches AC-18.1, the core cannot touch a file, parsing has its own AD, the Report has one builder and one writer, the Fixture Agent has a Suite surface, and `run` and `replay` share a pipeline. It is nearly safe to hand to story slicing, but three new high findings sit on the seams stories will meet first: the exit-3 path for an absent Trace is unreachable as AD-6 is written (a CI contract bug), `report --format html` and `compare --output` cannot be built without breaking the AD-15 CLI import test, and `reports.build_report(outcome, *, created_at)` is not given the identity, defaults, or Traces the Report seed requires. Fix those three plus the SuiteOutcome-constructor and Trace-write gaps (roughly fifteen sentences of rule text and a seed correction) and slicing can start; the remaining medium and low items can land as story-level corrections.

## New findings

- **[high]** Exit 3 for an absent Trace is unreachable (AD-6, AD-7, AC-27.3) — Unit A, the `runner` story, reads AD-6 literally: on `TraceMissingError` it calls the engine with `trace=None` and sets nothing; `SuiteOutcome.execution_failed` is set only on `AdapterRunError`. Unit B, the `engine` story, reads AD-6 literally: `trace is None` with `fail_on_missing_trace` true yields `error` results and sets no `ScenarioResult.execution_error` (that clause is written only for the `execution_error` argument). Composed, a run whose fixture file is missing with the default `fail_on_missing_trace: true` exits 1, not 3; AC-27.3 says 3 and the exit-code matrix test written from the PRD fails whichever unit lands second. A third builder sets `execution_failed` in the runner on `TraceMissingError` whenever the flag is true, so the CI contract depends on which runner story merged. *Fix:* in AD-6: "When `trace is None` and `defaults.fail_on_missing_trace` is true, `evaluate_scenario` sets `ScenarioResult.execution_error = "trace missing"` alongside the `error` results; when false it sets `skip_reason = "trace missing"` with `skipped` results. `SuiteOutcome.execution_failed` is derived, not assigned: `any(r.execution_error is not None for r in scenarios)`. `AdapterLoadError` and `ArtifactWriteError` reach `cli/app.py` as exceptions and exit 3 without a Report." Delete "sets `SuiteOutcome.execution_failed`" from the runner sentence.

- **[high]** `report --format html` and `compare --output` cannot be implemented under AD-15's CLI import test (AD-13, AD-15, AD-20, AD-11) — Unit A, the `report` command story, must call `reports.html.render(report)` and, for `--format json`, `reports.json_report.dumps(report)`; the `compare` command story must serialize a `Comparison` with `models.canonical.dumps`. None of those names is in `agentproof.__all__`, and `runner` exposes only `run_suite` and `replay` (AD-13). Unit B, the AD-15 test story, asserts the CLI imports only `__all__` names plus `io`. Composed, Unit A fails Unit B's test; the only "compliant" escape is to stuff rendering into `runner`, which AD-13 does not list, or into `cli`, which AD-13 forbids ("never assemble a Report"). The same hole covers `compare --output`: nothing public turns a `Comparison` into bytes. *Fix:* add to `__all__` in AD-15: `render_html(report: Report) -> str`, `dumps_report(report: Report) -> str`, `dumps_comparison(comparison: Comparison) -> str` (thin re-exports of `reports.html.render`, `reports.json_report.dumps`, and `models.canonical.dumps` over `comparison.model_dump(mode="json")`), and state in AD-20 that `report` and `compare` call exactly those plus `load_report` and `io.write_atomic`. Alternatively name the allowlist in the test: "`__all__` + `io` + `reports.html.render` + `reports.json_report.dumps` + `models.canonical.dumps`".

- **[high]** `reports.build_report(outcome, *, created_at)` cannot produce the seeded Report (AD-13, seed "Results and Report") — The seed Report carries `suite_id`, `run_id`, `package_version`, `schema_versions`, `defaults` (the Suite snapshot), and per-Scenario `trace`; `SuiteOutcome` is defined as `scenarios`, `suite_status`, `execution_failed`, `internal_error`, `evaluated_assertions`, and the seed says `Report` is "`SuiteOutcome` plus identity, counts, the Suite defaults snapshot, and embedded Traces". Unit A, the `reports.build` story, keeps the stated signature and therefore widens `ScenarioResult` to embed its `Trace` and widens `SuiteOutcome` to carry `suite_id`, `run_id`, and `defaults` (compliant: nothing forbids it). Unit B, the `engine` story, keeps `SuiteOutcome` and `ScenarioResult` as pure evaluation output with no identity and no Trace (compliant: AD-1 says the engine never sees ids or clocks; `evaluate_suite(suite, traces)` returns the same type for an API caller who has no run id). Composed, `build_report` is called with an outcome missing everything the Report needs, and the schema-drift test (AD-4) pins whichever model shape landed first. *Fix:* in AD-13: "`reports.build_report(outcome: SuiteOutcome, *, suite: Suite, traces: Mapping[str, Trace | None], run_id: str, created_at: str, package_version: str) -> Report`. `Report.defaults` is `suite.defaults` unchanged (the full `SuiteDefaults` model). `SuiteOutcome` and `ScenarioResult` carry no identity, timestamps, or Traces." Correct the seed `defaults` block to show every `SuiteDefaults` field (finding 9).

- **[medium]** `SuiteOutcome` has two constructors and `internal_error` has no writer (AD-6, AD-13, AD-15) — Unit A, the `runner` story, calls `evaluate_scenario` once per Scenario (it must, to pass `execution_error`) and assembles `SuiteOutcome` itself, computing `suite_status` with `combine` and `evaluated_assertions` by its own sum. Unit B, the `engine` story, implements `evaluate_suite(suite, traces) -> SuiteOutcome` for the public API with its own assembly. Both are compliant; the two assemblies can differ on `evaluated_assertions` (count results, or count non-skipped Scenarios) and on when `internal_error` is set (AD-6 reads it, AD-7 says exit 4 comes from the last-resort handler, nothing ever assigns it), so AC-34.2's "same Evaluation Result through API and CLI" holds for Scenarios and not for the suite-level fields. *Fix:* "`engine.evaluate.fold(results: Sequence[ScenarioResult]) -> SuiteOutcome` is the only constructor of `SuiteOutcome`; `evaluate_suite` and the runner pipeline both call it. `SuiteOutcome` has no `internal_error` field; exit 4 is produced only by the `cli/app.py` last-resort handler (fault injection raises inside the runner)." Drop `internal_error` from `from_outcome`.

- **[medium]** Golden files cannot be identical across the Linux/Windows matrix: `environment` and `package_version` are embedded but not volatile (AD-9, AD-11, AD-17, NFR-1, AC-20.2) — Unit A, the `runner` story, always overwrites `Trace.environment` with `Environment(package_version, python_version, os, source_revision)` from the running interpreter, including under `deterministic=True` (AD-9 says only `run_id`, `started_at`, `ended_at` change in that mode). Unit B, the golden-test story, strips exactly `VOLATILE_PATHS` and commits one golden `report.json` for the example Suite. Composed, the golden test passes on `ubuntu-latest` / 3.12 and fails on `windows-latest` / 3.15 at `scenarios[0].trace.environment.os` and `.python_version`, and on every release at `package_version` and `scenarios[*].trace.adapter.version`. *Fix:* in AD-9: "With `deterministic=True` the runner sets `run_id = "fixture-<scenario id>"` and leaves `started_at`, `ended_at`, and `environment` exactly as the adapter returned them." In AD-11 add to `VOLATILE_PATHS`: `package_version`, `scenarios[*].trace.environment`, `scenarios[*].trace.adapter.version`.

- **[medium]** Validate-then-overwrite forces adapters to invent the identity fields the runner discards (AD-9, AD-3, AC-5.3) — AD-9 re-validates the adapter's Trace through `loading.parse_trace` and only then overwrites `run_id`, `started_at`, `ended_at`, `environment`. Unit A, the `models.trace` story, makes `run_id` and `started_at` required `str` (the seed shows them non-null; FR-5 lists them as run-level fields). Unit B, a third-party adapter written from AD-9 ("whatever the adapter put there is discarded"), leaves them `None`. Composed, every Trace from Unit B fails validation before the overwrite and the run exits 3 with a validation message about fields the adapter was told not to care about; the conformance suite (AC-21.5) written by Unit A rejects Unit B's adapter and vice versa. *Fix:* in AD-9 and the seed: "`Trace.run_id`, `started_at`, `ended_at`, `environment` are `| None = None` on the model; `parse_trace` accepts null (AC-5.3 'when present'); an adapter may leave them null; the runner's overwrite makes them non-null in every Trace it writes; the conformance suite checks only that the returned Trace validates with `context.run_id` substituted." Alternatively overwrite first and validate the copy.

- **[medium]** Skipped Scenarios may still invoke the adapter, and precedence among `skip`, `trace is None`, and `execution_error` is unstated (AD-6, AD-9, AC-18.4) — Unit A, the `runner` story, calls `adapter.run` for every Scenario in declared order (nothing says otherwise) and passes whatever happens to the engine; for a skipped Scenario without `scenario.trace`, the Fixture Agent raises `TraceMissingError` and the engine receives `skip="reason"` with `trace=None`. Unit B, the `engine` story, checks conditions in the order it finds convenient: `execution_error` first (an adapter raise must never hide), then absence, then `skip`. Composed, a `skip`ped Scenario reports `error`, sets `execution_error`, and the run exits 3; a live-adapter Suite spends model credits on skipped Scenarios. *Fix:* in AD-6: "`evaluate_scenario` applies, in this order, `scenario.skip`, then `execution_error`, then `trace is None`; the first that holds decides every result." In AD-9: "The runner never calls `Adapter.run` for a Scenario with `skip` set; it calls the engine with `trace=None`."

- **[medium]** Writing `scenario-<id>.trace.json` is absent from the pipeline, so `replay` may write it over a `run`'s evidence (AD-13, AD-14, AC-6.4, AC-19.4) — AD-13's pipeline is obtain → redact → evaluate → build_report → write_atomic; the per-Scenario Trace file named in AD-14 is written by no listed step. Unit A, the `runner` story, writes the redacted Trace inside the shared pipeline so `run` and `replay` behave identically, and `trace replay --output ./agentproof-output` overwrites `scenario-reject-over-limit.trace.json` from the last `run`, which AC-19.4 forbids. Unit B writes Trace files only from `run`'s loop, so a replay leaves no Trace, and the e2e story that expects "the redacted Trace next to the replay Report" fails. *Fix:* in AD-13: "`run` writes each produced Trace to `scenario-<id>.trace.json` through `write_atomic` after redaction and before evaluation; `replay` writes only `replay-<id>.report.json`."

- **[medium]** `Report.defaults` snapshot shape is two different models (AD-13, seed Suite vs seed Report, AD-19) — The seed Report's `defaults` shows `fail_on_missing_trace`, `compare`, `redact` and omits `adapter` and `fixture`; AD-19 says `canonical.dumps` writes every field. Unit A, the `models.report` story, types `defaults: SuiteDefaults` (five keys serialized). Unit B, writing the golden file and `schemas/report-v1.schema.json` fixtures from the seed, uses three keys and a separate `ReportDefaults` model. The drift test (AD-4) and the golden test disagree with each other. *Fix:* "`Report.defaults: SuiteDefaults`, serialized in full; the `adapter` value is the Suite's declared one, not the `--adapter` override, which is recorded in `scenarios[*].trace.adapter`." Correct the seed.

- **[medium]** `redact.keys` semantics: extend or replace the default set (AD-10, seed Suite, FR-31) — The seed Suite declares `redact: {keys: [], paths: [], env: [...]}` and the seed Trace shows `arguments.api_key` redacted. Unit A, the `redaction.rules` story, treats `keys` as additions to the four defaults (so `[]` means defaults only). Unit B treats `keys` as the full set (so `[]` disables key redaction, matching the usual "explicit list wins" convention). Composed, the `init` example either redacts `api_key` or does not, and AC-31.3's planted value leaks under Unit B with the shipped template. *Fix:* in AD-10: "`redact.keys` extends the default key set; the defaults cannot be removed in v0.1. `redact.paths` are event-relative dotted paths with the AC-14.1 syntax prefixed by the section name (`arguments.items.0.secret`, `output`, `metadata.headers.cookie`)."

- **[medium]** `RedactionState.paths` and `env_names` content is defined two ways (AD-10 vs seed Trace, AC-31.2) — AD-10 says `paths` are "the configured rule strings that matched" (a default-key rule is `api_key`); the seed Trace records `arguments.api_key` (a hit location). `env_names` is "unioned" without saying whether a configured name is recorded when its value is set but never found. Unit A records rule strings and all configured names; Unit B records hit paths and only names whose value was replaced at least once; both sort or do not sort the union. Golden files, `scrub` idempotence tests, and the HTML "redacted" labels disagree. *Fix:* "`paths`: sorted, deduplicated, event-relative hit paths (`arguments.api_key`, `output`); `env_names`: sorted names whose value was replaced at least once in any pass; both unioned with the incoming state."

- **[medium]** Rules for modules outside the layer stack have no named contract, and the layer contract lets `cli` import the core (AD-2, AD-13, AD-15) — AD-2 names the layer contract "the authority", then states in prose that `io`, `adapters`, `runner`, and `cli` import only listed packages. import-linter's layers contract does not check `io` or `adapters` at all (they are not layers), and places `cli` on top, so `cli` importing `engine` passes `lint-imports`. Unit A, the `compare` command story, imports `agentproof.compare.compare` and `agentproof.loading.report.parse_report` directly (passes the authority). Unit B's AD-15 test asserts `__all__`-only imports and fails Unit A. *Fix:* in AD-2: "The `.importlinter` file holds the layer contract above plus three `forbidden` contracts, reproduced here: `agentproof.io` may not import `models`, `loading`, `assertions`, `engine`, `reports`, `compare`, `adapters`, `runner`, `cli`; `agentproof.adapters` may not import `assertions`, `engine`, `reports`, `compare`, `runner`, `cli`; `agentproof.cli` may not import `models`, `loading`, `redaction`, `assertions`, `engine`, `reports`, `compare`, `adapters` (it reaches them through `agentproof.__all__`). `agentproof.testing` may import everything except `cli`." Add `testing` to the outside-the-stack list.

- **[medium]** `trace replay` with a missing `TRACE_PATH` exits 2 in the spine and 3 (or skipped) in the PRD (AD-7, AD-14, AD-20 vs AC-18.2, AC-27.3) — AC-18.2 defines "the Trace file named for Replay does not exist" as an absent Trace governed by `fail_on_missing_trace`; the spine's CLI reads `TRACE_PATH` through `io.read_limited`, which raises `PathError` (`InputError`, exit 2) before `runner.replay` sees anything. Two CLI builders diverge: one passes `trace_bytes=None` into `replay` to honour AC-18.2, the other lets `PathError` propagate. *Fix:* decide once and record it: keep exit 2 (a mistyped path is input, and `replay` already takes bytes) and add the line to the ADR log's "Upstream conflicts": "AC-18.2's replay clause is implemented as `PathError` (exit 2); the `fail_on_missing_trace` flag applies to `run` only."

- **[low]** `run_id` cardinality and `Report.run_id` under deterministic mode and replay are unspecified (AD-9, Conventions "Ids", seed) — one UUID4 per `run_suite` call copied into every Trace and the Report, or one per Scenario (the deterministic rule `fixture-<scenario id>` is per Scenario, which suggests the latter); `Report.run_id` for a deterministic run or a replay has no rule. *Fix:* "One UUID4 per `run_suite` call, placed in every `RunContext` and in `Report.run_id`; under `deterministic=True`, `Trace.run_id = "fixture-<scenario id>"` and `Report.run_id = "fixture-<suite id>"`; `replay` sets `Report.run_id` to the replayed Trace's `run_id`."

- **[low]** `redact_trace` cannot be called from the public API as specified (AD-10, AD-15) — `redaction.redact(trace, rules, secret_values)` takes a `RedactionRules`, which is neither exported nor constructible from `SuiteDefaults` by any public function. *Fix:* "`redact_trace(trace: Trace, defaults: SuiteDefaults, secret_values: Sequence[str]) -> Trace`; `RedactionRules` is built internally from `defaults.redact`."

- **[low]** AD-1's ban on "`pathlib.Path` I/O methods" is not lintable, and `models/export_schemas.py` must write files (AD-1, AD-4, seed) — ruff TID251 bans qualified names on import or attribute access, not methods on an instance; `export_schemas` lives in `models` (core) and needs `open` or `Path.write_text`. *Fix:* ban the `pathlib` module and `builtins.open` in core, keep a `tests/unit/test_core_has_no_open.py` grep as the backstop, and move the exporter to `cli/commands/schemas.py` (hidden command) or `scripts/export_schemas.py` outside the package.
